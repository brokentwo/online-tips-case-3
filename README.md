# Кейс 3. Онлайн-чаевые: решение

Заполненные шаблоны кейса, прототип и тесты. В папке `ДАННЫЕ` лежат CSV организаторов без изменений.

## Как запустить

```bash
python3 tests_t3.py
python3 tests_mutation.py
python3 04_прототип.py dialog qr_002
```

Один запрос из файла: `python3 04_прототип.py запрос.json`, например `{"qr_id": "qr_001", "base_amount": 637.00, "tip_pct": 5}`.
Поле `action`: `pay` (по умолчанию), `create`, `confirm`, `cancel`, `qr_info`, `qr_generate`, `report`.
Нужен Python 3.9 или новее, сторонних библиотек нет. Прототип ищет данные в папке `ДАННЫЕ` рядом с собой или уровнем выше, путь можно задать через `TIPS_DATA_DIR`.

Результат от 01.11.2026 на одном Mac: 23 из 23 проверок, 37 из 37 намеренных поломок замечено. Факты тестов записаны в `test_results.md`.

## Противоречия в материалах и наши решения

| Что не сходится | Что сделали | Что уточнить |
|---|---|---|
| Формула `md5(qr_id + nonce) % 10` даёт qr_001 код 9 (таймаут) и qr_003 код 7 (успех). T3-1 ждёт SUCCESS, T3-2 ждёт DECLINED | qr_001 и qr_003 закреплены как контрольные в `CONTROL_CODES`, для остальных 98 QR работает формула. В ответе видно `control_qr` | Какая формула у организаторов |
| В `payments.csv` строка p_0003 с теми же суммами, что в T3-2, имеет статус SUCCESS | `payments.csv` считаем историей: её статусы идут по номеру строки и с формулой не связаны | Подтвердить |
| Все `exp` в `qr_links.csv` относятся к 1–4 ноября 2025, по настоящим часам все QR просрочены | Часы прототипа стоят на `2025-11-01T18:00:00Z`, время из шаблона. Поле `now` в запросе их переводит | Нет |
| В файле `08_errors.md` лежит шаблон ER-модели, каталога ошибок нет. `10_tests.md` тоже нет | Коды собраны из подсказок в шаблонах и таблицы `ERRORS` в прототипе | Прислать настоящий файл |
| P-3 (итог больше 2 000 000) недостижим: при P-1 и Q-6 итог не выше 1 500 000 | Проверка оставлена как страховка и проверена с поднятым лимитом чека | Нет |
| По одному QR возможны несколько платежей, но nonce одноразовый | Nonce занят, пока платёж в CREATED, PENDING или SUCCESS. После DECLINED и CANCELED можно пробовать снова | Нет |
| Отчёт в образце: `tips_total = sum(tip)` без учёта статуса | Деньги считаем только по SUCCESS: при отказе и отмене чаевых никто не получил. Для m_001 это 414,85 ₽ вместо 611,20 ₽ | Подтвердить |
| Три структуры слайдов: в docx, в `05_презентация.md` и в общей инструкции | Порядок взят из docx, титул, схема и Git добавлены из общей инструкции, демо показано на слайде с тестами | Какая главная |

## Известные ограничения прототипа

- Сумма чека приходит в запросе и не входит в подпись: 6 полей QR заданы шаблоном. В боевой версии сервер должен брать её из кассы по `receipt_id`.
- Подпись в запросе необязательна, чтобы работал формат `qr.json` из шаблона. В API она должна быть обязательной, иначе номера `qr_NNN` легко перебрать.
- Лимита запросов нет: в консольной программе нет адреса клиента. NFR описан, но не реализован.
- CSV не защищён от параллельной записи, HTTP-сервера нет, картинку QR прототип не рисует, только ссылку.
- Регистрация мерчанта и сотрудника описана в `02_roles.md`, в прототипе её нет.
