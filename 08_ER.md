# ER-модель — кейс 3 «Онлайн-чаевые»

В материалах этот шаблон лежит под именем `08_errors.md`, а `06_приложение.md` называет его `08_ER.md`. Каталог ошибок вынесен в отдельный файл `08_errors.md`.

Диаграмма: `схемы/er_модель.drawio`.

## 1. Сущности (6)

| Сущность | Что хранит | Зачем |
|---|---|---|
| Merchant | merchant_id, name, status, description | справочник мерчантов |
| Employee | employee_id, merchant_id, name, payment_details (маска) | официанты и их привязка к мерчанту |
| QR | qr_id, merchant_id, employee_id, receipt_id, nonce, exp, signature | одноразовая подписанная ссылка на оплату чека |
| Payment | payment_id, qr_id, amount, tip, status, timestamp | факт оплаты: чек и чаевые |
| Report | report_id, merchant_id, period, tips_total | агрегаты для отчётности |
| AuditEvent | event_id, payment_id, qr_id, action, from_status, to_status, amount_total, actor, at | журнал событий для разбора |

## 2. Атрибуты

### 2.1. Merchant

| Поле | Тип | PK/FK | Обяз. | Ограничение |
|---|---|---|---|---|
| merchant_id | string | **PK** | да | `m_NNN` |
| name | string | — | да | 1–100 |
| status | enum | — | да | ACTIVE/BLOCKED/PENDING |
| description | string | — | нет | 0–200 |

### 2.2. Employee

| Поле | Тип | PK/FK | Обяз. | Ограничение |
|---|---|---|---|---|
| employee_id | string | **PK** | да | `e_NNN` |
| merchant_id | string | FK → Merchant | да | `m_NNN` |
| name | string | — | да | 1–100 |
| payment_details | string | — | да | только маска `****NNNN` |

### 2.3. QR

| Поле | Тип | PK/FK | Обяз. | Ограничение |
|---|---|---|---|---|
| qr_id | string | **PK** | да | `qr_NNN` |
| merchant_id | string | FK → Merchant | да | `m_NNN` |
| employee_id | string | FK → Employee | да | `e_NNN`, сотрудник этого мерчанта |
| receipt_id | string | — | да | `r_NNNN`, уникален для мерчанта |
| nonce | string | — | да | 6 hex, одноразовый |
| exp | datetime | — | да | ISO 8601, TTL 24 ч |
| signature | string | — | да | HMAC-SHA256, 16 hex |

### 2.4. Payment

| Поле | Тип | PK/FK | Обяз. | Ограничение |
|---|---|---|---|---|
| payment_id | string | **PK** | да | `p_NNNN` |
| qr_id | string | FK → QR | да | `qr_NNN` |
| amount | decimal | — | да | > 0, ≤ 1 000 000 |
| tip | decimal | — | да | ≥ 0, ≤ amount × 0.5 |
| status | enum | — | да | CREATED/PENDING/SUCCESS/DECLINED/CANCELED |
| timestamp | datetime | — | да | ISO 8601 |

В `payments.csv` нет `qr_id`, вместо него лежат `merchant_id` и `employee_id`. Прототип сохраняет 7 колонок файла, а связь с QR хранит в `payment_index.csv`.

### 2.5. Report

| Поле | Тип | PK/FK | Обяз. | Ограничение |
|---|---|---|---|---|
| report_id | string | **PK** | да | `rep_NNNN` |
| merchant_id | string | FK → Merchant | да | `m_NNN` |
| period | string | — | да | `YYYY-MM` |
| tips_total | decimal | — | да | ≥ 0 |

Прототип считает отчёт по запросу из платежей и не хранит его. Таблица Report нужна боевой версии, чтобы не пересчитывать закрытые месяцы.

### 2.6. AuditEvent

| Поле | Тип | PK/FK | Обяз. | Ограничение |
|---|---|---|---|---|
| event_id | string | **PK** | да | `evt_NNNN` |
| payment_id | string | FK → Payment | нет | пусто у отказов QR, платежа там нет |
| qr_id | string | FK → QR | да | `qr_NNN` |
| action | string | — | да | payment_created / payment_pending / payment_confirmed / payment_declined / payment_timeout / payment_canceled / invalid_qr / qr_expired |
| from_status | enum | — | нет | статус платежа, пусто у первого события |
| to_status | enum | — | нет | статус платежа, пусто у отказов QR |
| amount_total | decimal | — | нет | итог платежа |
| actor | string | — | да | system / client / officer |
| at | datetime | — | да | ISO 8601 |

Поля `qr_id` и `amount_total` добавлены к шаблону из подсказок `11_ИБ.md`.

## 3. Связи

| Связь | Тип | Обоснование |
|---|---|---|
| Merchant → Employee | 1:N | у мерчанта много официантов, у официанта один мерчант |
| Merchant → QR | 1:N | мерчант выпускает QR на каждый чек |
| Employee → QR | 1:N | у официанта много чеков |
| QR → Payment | 1:N | после отказа или отмены возможна новая попытка, успешная только одна |
| Merchant → Report | 1:N | один отчёт на мерчанта за период |
| Payment → AuditEvent | 1:N | каждый переход статуса — отдельное событие |

## 4. Диаграмма (draw.io)

`схемы/er_модель.drawio`: 6 сущностей с PK/FK и связями `1` и `N`. PNG для Приложения можно экспортировать из draw.io.
